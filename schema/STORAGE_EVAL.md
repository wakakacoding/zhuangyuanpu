> 评估日期：2026-10-13 · 评估人：站内自查
> 结论：**不迁移，YAML + Git 继续。** 下次评估触发条件：全量构建 > 2 分钟，或出现多人协作冲突。

## 判断

1. **性能远未触顶**：构建耗时大头在 Astro 固定开销，YAML 解析占比极小；即使人物卡膨胀 10 倍（每卡补全 event/source 引用），按线性外推仍 < 20s。
2. **YAML + Git 的协作红利仍在**：每张卡一个文件，diff 可读、勘误留痕天然（开发方案 R6 纪律：编辑器 + Git 就是后台）。
3. **检索无需数据库**：/search 页构建期内嵌 600 条精简索引（144KB 未压缩），客户端过滤毫秒级。
4. **SQLite 的真实成本**：引入构建层转换脚本 + 查询层，多一个故障点；当前规模下收益为零。

## 何时重启评估

- 全量构建 > 2 分钟（开发方案硬性门槛）；
- 关系边数量级增长（力导向网络图需要邻接查询）；
- 开放只读 API（Phase 4）且静态 JSON 文件不敷使用时。
